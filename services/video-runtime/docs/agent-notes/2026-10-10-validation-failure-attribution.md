# Validation failure attribution

A failed continuous `validate` task reached the Agent with category `invalid_input`, because keyword classification maps the word "validation" in `Artifact validation failed: …` to invalid input, and its failure payload named only the validate task. The scheduler already persisted every `ValidationResult` of the attempt, including `artifact_version_id` and `validator_id`, in a `validation_result` report before failing the step; no consumer read it back. PlanPatch admission resolves capabilities through the Skill catalog, which does not list validators, so a continuous `validate` task exists only when the Agent submits one through `video_checkpoint_resolve` under a catalog capability id.

Task snapshots now derive attribution from that report. A failed validate task with at least one conclusive failing result that names an ArtifactVersion reports category `quality_rejected`, trigger source `validator`, and `rejected_artifacts`: each entry names the rejected ArtifactVersion, the validate task's dependency whose BuildStep holds that version, the validator, and its issues, bounded like other checkpoint values. The checkpoint notification, checkpoint refresh and inspection, and the Studio task list share one derivation over persisted records, so redelivery, restart and later validate tasks report the same attribution for the same report. Each validate attempt clears the step's report reference before it runs, because a requeued step keeps its previous attempt's reference; an attempt that fails before staging a report is not attributed. No field or schema is added: the attribution reaches durable state only as text inside the persisted checkpoint `planner_instruction`, and validators record `inconclusive` in the existing `ValidationResult.metadata`.

Enforcement is unchanged. A task whose error classifies as content moderation keeps the moderation payload, so its category agrees with the classification moderation repair applies to the same error text. A report with no conclusive failing result keeps the previous payload; the continuity validator marks a result inconclusive when its only issue is a failed VLM inspection or ffprobe call. Staged validate failures stage no report and are unchanged. Repair budgets, validator admission and staged repair eligibility are out of scope.

Regression coverage is `tests/video_runtime/test_validation_attribution.py`; `tests/video_runtime/snapshots/quality-rejected.json` records the agent-visible payload.
